The Problem
Support agencies answer the same questions all day.
Coding Media, a software & design agency, was manually handling every website inquiry — repeating the same service explanations, missing leads outside business hours, and losing track of who'd already been contacted. This chatbot owns that entire first conversation: understand the need, answer from real company knowledge, capture the lead, and book the follow-up call — without a human touching it.
How a message flows
Request to response, step by step
Every message goes through the same pipeline, whether it's a simple question or something that needs a database write.
01

Widget sends the message

A vanilla-JS widget (Shadow DOM, so it never clashes with a host site's CSS) posts the message + a session ID to the FastAPI backend.

02

Cache & daily-cap check

Redis is checked first — for repeated FAQ-style questions, and for a global daily message cap that protects the shared LLM quota.

03

LangGraph agent decides

Groq (via LangGraph's tool-calling) decides: answer directly, search the knowledge base (ChromaDB + RAG), or call one of 7 MCP tools.

04

Tools do the real work

Capture a lead into PostgreSQL, check Google Calendar for open slots, book a meeting (with automatic duplicate-booking prevention), or pull a past case study.

05

Response + side effects

The reply streams back to the widget. In parallel: conversation history is saved to Redis, and the team gets an email if a new lead came in or the bot couldn't answer something.

What it actually does
Seven tools, one agent

Knowledge search

Answers from real company FAQs and service docs via RAG — never invents prices, capabilities, or case studies.

Lead capture

Creates a client profile + order in Postgres, with duplicate-lead detection so the same request doesn't get logged twice.

Meeting booking

Checks live Google Calendar availability, books the slot, and auto-cancels any prior booking if the client reschedules.

Client memory

Merges a client's past orders and human call notes into one context, so returning clients aren't asked to repeat themselves.

Admin dashboard

JWT-protected panel for the team: view leads, meetings, unanswered questions, and log call notes.

Encrypted at rest

Sensitive fields (requirements, call notes) are Fernet-encrypted transparently at the ORM layer.

Drop it into any website

The widget is a single, dependency-free script tag. It works on WordPress, Webflow, a plain HTML site, or anything else — no framework, no build step.

<script src="chatbot-widget.js" data-api-url="https://your-backend.com/api/chat" data-agency-name="Your Company" ></script>
Currently live at codingmedia.in — deployed on Render (API) + Supabase (Postgres) + Upstash (Redis), all on free tiers.
Tech stack
What's under the hood
BackendFastAPI (async), Uvicorn
OrchestrationLangGraph — agent + tool node, conditional routing
LLMGroq (openai/gpt-oss-120b), native tool-calling
RAGChromaDB + HuggingFace multilingual embeddings
ToolsMCP (Model Context Protocol) — 7 custom tools
DatabasePostgreSQL (Supabase) + SQLAlchemy async + Alembic
Cache/sessionRedis (Upstash) — conversation history + response cache
CalendarGoogle Calendar API, timezone-aware (IST)
AuthJWT (admin), bcrypt password hashing
FrontendVanilla JS, Shadow DOM — zero framework dependency
HostingRender (API) · GitHub Pages (widget/admin) · fully free tier
